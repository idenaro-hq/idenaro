## chains-overview | Chain Findings | 

Chain findings are generated by the correlation engine after all individual module checks complete. They identify combinations of co-occurring weaknesses that together create a higher-severity attack path than any single finding alone. A chain finding signals that an attacker can combine two or more weaknesses into a realistic exploit sequence.

### Checks performed

- Admin exposure combined with weak session security (no HttpOnly / no Secure)
- Missing MFA combined with an exposed admin endpoint
- Implicit OAuth flow active alongside weak Content-Security-Policy
- Missing HSTS combined with insecure cookie flags
- Open redirect on logout combined with active OIDC flow
- User enumeration capability combined with absent MFA
- Exposed SCIM endpoint combined with weak access control indicators
- CORS misconfiguration combined with a sensitive unauthenticated API
- Multiple debug or admin endpoints exposed simultaneously

---

## chain-admin-session | Chain: Admin Exposure + Weak Session Security | CRITICAL

An admin panel is publicly accessible *and* session security controls are weak (missing Secure/HttpOnly flags or HSTS). Together, these create a direct path to administrative compromise: an attacker who intercepts any session token via SSL stripping or XSS gains immediate admin access.

### Remediation Priority

- Treat this as a coordinated remediation, not two separate issues.
- Restrict admin access to VPN/internal network first (minutes to implement, maximum impact).
- Add Secure + HttpOnly + SameSite=Strict to all session cookies.
- Enable HSTS to prevent SSL stripping.

---

## chain-mfa-admin | Chain: Missing MFA + Exposed Admin Endpoint | CRITICAL

No MFA indicators are detected *and* an administrative endpoint is publicly accessible. A single compromised password - via phishing, credential stuffing, or data breach - grants full administrative access to the identity system with no additional barrier.

### Remediation Priority

- Restrict admin endpoint access to internal network or VPN immediately.
- Enable MFA for all user accounts, particularly administrators.
- Both issues must be addressed - fixing only one leaves critical exposure.

---

## chain-implicit-csp | Chain: Implicit Flow + Weak CSP | HIGH

OIDC implicit flow is enabled *and* the login page has a weak or absent Content Security Policy. An XSS vulnerability on the login page can steal access tokens that are transmitted via URL fragment - a combination that makes token theft trivially easy.

### Remediation Priority

- Disable implicit flow and migrate to Authorization Code + PKCE.
- Implement a strict CSP with nonces to prevent XSS on the login page.

---

## chain-hsts-cookies | Chain: Missing HSTS + Insecure Cookie Flags | HIGH

HSTS is absent *and* session cookies lack the Secure flag. This combination enables a complete SSL stripping attack: an attacker on the network path downgrades HTTPS to HTTP, and session cookies are transmitted in plaintext without any browser-level protection.

### Remediation Priority

- Add the Secure flag to all session cookies.
- Enable HSTS with a long max-age to prevent future HTTP connections.

---

## chain-redirect-oidc | Chain: Open Redirect + OIDC Flow Active | HIGH

An open redirect is present *and* OIDC is configured. Open redirects in OIDC authorization flows are directly exploitable for authorization code theft: an attacker crafts an authorization URL with the open redirect as the redirect_uri, and the authorization code is delivered to the attacker.

### Remediation Priority

- Validate all redirect parameters against a strict allowlist.
- Ensure the OIDC authorization endpoint validates redirect_uri against registered values only.

---

## chain-enum-mfa | Chain: User Enumeration + No MFA | HIGH

User enumeration is possible *and* MFA is absent. Enumerated usernames can be directly targeted in credential stuffing or password spray attacks with no MFA friction to slow the attack or limit impact.

### Remediation Priority

- Fix user enumeration by returning identical responses for valid and invalid accounts.
- Enable MFA for all accounts to add a second barrier even if passwords are compromised.

---

## chain-scim-iac | Chain: SCIM Exposed + Weak Access Controls | CRITICAL

A SCIM provisioning endpoint is accessible *and* other access control weaknesses are present. SCIM provides full CRUD over user identities. Combined with other IAM weaknesses, an attacker can enumerate users, escalate privileges, and maintain persistent access through provisioned accounts.

### Remediation Priority

- Immediately restrict SCIM access to authenticated provisioning systems only.
- Address the accompanying access control findings to eliminate the combined attack path.

---

## chain-cors-api | Chain: CORS Misconfiguration + Sensitive API | HIGH

CORS is misconfigured on an auth-sensitive endpoint *and* sensitive API endpoints are accessible. Any authenticated user who visits a malicious website can have their session used to make cross-origin requests to the auth API, enabling CSRF-scale attacks against the identity system.

### Remediation Priority

- Fix CORS policy to use a strict origin allowlist.
- Ensure all auth API endpoints require CSRF tokens in addition to session authentication.

---

## chain-multi-endpoints | Chain: Multiple Debug/Admin Endpoints Exposed | HIGH

Three or more sensitive endpoints are publicly accessible simultaneously. This is not an isolated misconfiguration but indicates a systemic absence of deployment hardening. Each exposed endpoint provides different information or access that compounds the overall attack surface.

### Remediation Priority

- Conduct a full audit of all exposed endpoints beyond those found by the scanner.
- Implement a default-deny policy at the reverse proxy layer for all management paths.
- Restrict all admin, debug, and monitoring endpoints to internal networks as a class.
